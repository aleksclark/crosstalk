# Step 04: TypeScript + Go Client Generation

## Goal

Both a TypeScript and a Go API client are generated from the server's OpenAPI spec. No hand-written API clients — types flow from server → spec → clients automatically.

## Approach

1. Server exports `api/openapi.json` (generated by Huma at build time)
2. TypeScript client generated with `openapi-typescript` + `openapi-fetch`
3. Go client generated with `oapi-codegen`

Both clients get full type safety — request/response types match the server exactly.

## Tasks

- [ ] `task api:spec` — runs server, dumps `/api/openapi.json` to `api/openapi.json`
- [ ] Committed to repo (so clients can generate without running server)

### 4.2 TypeScript client

### 4.3 Go client

- [ ] `task api:generate:go` — regenerates from spec

### 4.4 Generation pipeline
- [ ] `task api:generate` — runs all generators in sequence

## Directory Structure

```
api/
  openapi.json          # Generated spec (committed)
packages/
  api-client/           # Shared TS client package
    src/
      types.ts          # Generated from openapi.json
      client.ts         # openapi-fetch wrapper with auth
      index.ts          # Re-exports
    package.json
client/                 # Generated Go client module
  go.mod
  client.go             # Generated client interface
  types.go              # Generated request/response types
```

## TypeScript Client Usage

```typescript
import { createClient } from '@crosstalk/api-client'

const api = createClient({
  baseUrl: 'https://ct.example.com',
  token: jwtToken,
})

const { data: sessions } = await api.GET('/api/sessions')
// sessions is fully typed as Session[]
```

## Go Client Usage

```go
import "github.com/aleksclark/crosstalk/client"

c, _ := client.NewClient("https://ct.example.com", client.WithBearerToken(token))
sessions, _ := c.ListSessions(ctx)
// sessions is []client.Session with full type safety
```
